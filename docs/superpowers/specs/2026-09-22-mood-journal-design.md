# 情绪日记与自我关怀：第一版产品设计

日期：2026-09-22  
状态：对话设计已确认，本文待用户审阅。本文批准后再编写实施计划。

## 1. 目标与范围

面向初入职场的年轻人，设计用于课程作业与作品集展示的自我洞察工具。用户完成“记录情绪—查看关联—尝试关怀—回顾变化”的闭环。最终发布到 GitHub Pages。

已确认的方向：本地分析真实可用；预留 AI 入口，仅展示明确标注的预设示例解读。第一版不调用模型，不发送个人日记，不提供账户、跨设备同步、社交功能或心理诊断。

成功标准：评审无需积累日记就能通过虚构示例体验完整流程；个人用户可以从空白开始记录、刷新后继续使用，并能追溯每条洞察的依据。没有数据或证据不足时不生成虚假结论。

## 2. 空间与入口

首次访问提供“体验示例故事”和“开始我的记录”。后续记住上次空间，顶部持续提供切换入口。

- 示例空间：内置一位虚构职场新人的连续两周记录，包含不同情绪、事件及关怀前后反馈。始终标识“示例体验 · 虚构数据”。新增、修改及删除只影响独立的示例副本，支持重置。
- 示例首次初始化或主动重置时，将故事的相对日期映射到截至昨天的两周，后续不会静默改写日期；若长期未访问导致示例超出分析范围，提示重置示例。固定 AI 材料使用“第 1 天”等故事日期，不依赖真实日历日期。
- 个人空间：从空白开始。所有日记与关怀记录只保存在当前浏览器，不混入示例。
- 两个空间分别保存数据；每次读写必须显式指定空间，不以界面标签作为唯一隔离措施。
- AI 示例的源材料使用固定的原始示例数据，不跟随可编辑示例副本变化。展示固定材料并注明“预设解读”，防止用户编辑后产生错误引用。

## 3. 信息架构与视觉

使用“记录、洞察、关怀、回顾”四个页面。桌面端顶部导航，移动端底部四栏导航。数据管理通过次级入口进入。

整体采用安静、清晰的个人观察手账风格：暖白背景、深灰文字、低饱和蓝绿色主色，适量留白，减少装饰。情绪通过文字与柔和颜色共同表达，不仅靠红绿区分。图表以清楚呈现证据为先。

### 记录页

顶部日期与“此刻，你感觉怎么样？”，依次填写感受、具体情绪、强度、事件与文字。保存后提供查看记录和进入关怀的入口。

### 洞察页

按顺序展示时间范围选择、情绪趋势、事件关联、关怀反馈，最后提供 AI 示例入口。每项结论显示样本数及“查看依据”。个人空间数据不足时展示已有数据和积累提示。

### 关怀页

根据用户选择的当前情绪或本次刚保存的日记推荐一项活动，说明依据，同时允许自由选择其他活动。不直接把久远日记视为当前状态。活动时进入简洁专注界面，退出按钮始终可见。

### 回顾页

按日期倒序分组展示日记及关怀活动，可按情绪、事件筛选日记，展开详情进行编辑和删除。活动记录可查看、删除；删除后反馈统计同步更新。删除操作须确认。

## 4. 情绪记录

每条日记包含：

| 字段 | 规则 |
| --- | --- |
| 发生时间 | 默认当前本地时间，可补记过去时间，不允许未来时间；一天可多次记录 |
| 整体感受 | 必填，1–5 分：很不好、不太好、一般、比较好、很好 |
| 具体情绪 | 必填、多选：焦虑、烦躁、低落、疲惫、平静、开心、期待、满足 |
| 整体情绪强度 | 必填，1–5 级：很轻、较轻、中等、较强、很强；不等同于感受好坏 |
| 相关事件 | 可选、多选：工作任务、人际沟通、通勤、睡眠、运动、个人生活 |
| 日记文字 | 可选，最多 5000 字，以纯文本保存与显示 |

事件标签由用户选择，不从文本自动推断。“相关事件”不等于已确认的情绪原因。不同情绪允许共存，第一版不按每种情绪分别填写强度。

日记支持新增、编辑、删除。保存成功后才清空输入；失败保留表单并提供重试。离开有未保存修改的编辑页时提示确认。

## 5. 本地洞察规则

所有指标仅使用当前空间、所选时间范围内的数据，由确定性函数计算。范围为包含今天的最近 7 或 30 个本地自然日。按记录发生时间筛选，不按创建时间筛选。保存记录时保留发生日期，避免切换时区后静默重新分组。

### 5.1 情绪趋势

按日计算整体感受的算术平均值，显示当天记录数，保留一位小数。缺失日期留空，不插值，不跨缺失点画连续线。可打开某日全部原始记录。单条记录也可显示，不伪造趋势判断。

### 5.2 事件关联

每个标签计算相关记录的平均感受，与同期全部日记的平均感受比较。多标签记录可分别参与多个标签组，但全体平均只计一次。

只有同时满足以下条件才显示比较结论：同期至少 7 条日记；该标签至少 3 条日记；同期至少存在 1 条不含该标签的日记。不含该标签的记录可以未填写事件。

结论格式为“标记工作任务的 N 条记录，平均感受 X；同期整体为 Y”，可用“较高／较低／相同”描述原始均值差异，并显示四舍五入后的数值；若显示精度下两数相同，则统一描述“接近”。结论不使用导致、证明、诊断等措辞。显示“样本有限，仅反映当前记录中的关联”。这些门槛是产品展示规则，不代表统计显著性。

固定按事件标签顺序展示符合门槛的结果，不以显著性、因果性或预测能力排名。点击依据可查看标签组及同期其他记录。

### 5.3 关怀反馈

只使用完成活动且前后自评都存在的记录，按活动结束日期计入时间范围。变化值为结束感受减开始感受。按活动类型显示配对次数、平均变化、改善／不变／下降次数，并可查看每次反馈。

一次有效配对也可展示，但标注样本数，不称为最佳疗法或证明有效。未改善的反馈照常保存，不做正向美化。

## 6. 关怀活动

第一版提供三种直接可体验的活动：

| 活动 | 交互 |
| --- | --- |
| 呼吸练习 | 约 1 分钟舒缓呼吸提示，无强制屏息；可暂停、退出，提示按舒适节奏进行 |
| 声音陪伴 | 至少一段可合法发布的环境音；主动播放、音量、时长选择和停止控制，不自动播放 |
| 轻量活动 | 3–5 分钟的散步、舒适肩颈放松或离屏休息提示，可自行完成或退出 |

建议规则采用透明的固定映射：焦虑／烦躁优先呼吸，疲惫优先离屏休息，其余默认声音陪伴。多情绪时按上述顺序决定首推，并展示实际匹配依据。没有当前情绪时直接自由选择，不猜测。

活动前后均可填写与日记相同的五档整体感受，可跳过，不自动替用户沿用此前日记分数。只有显式填写的两次评分才构成配对。

活动有进行中、暂停、已完成、已退出、已中断状态；退出或中断不计为完成、不进入效果统计。刷新时停止音频，将未完成会话视为中断，不在后台宣称已完成；可以重新开始。完成状态和反馈保存失败时保留当前操作状态并提示重试。

无连续打卡惩罚、排行榜、完成后必然变好的承诺。整体定位为日常自我记录与关怀，简短说明不能替代专业帮助，不将普通情绪记录自动解释为疾病。

## 7. AI 示例解读

示例由预先撰写内容组成：观察到的模式、可能的解释、一个反思问题。每条观察链接到固定示例材料。

- 入口和内容均标记“AI 解读示例 · 预设内容，非实时生成”。
- 个人空间入口名为“查看 AI 解读示例”，明确说明不会分析或发送个人日记。
- 不设置虚假的生成等待、调用状态或“已分析你的日记”等文案。
- 第一版不提供密钥输入框、不调用外部 AI、不引入无实际用途的代理服务。
- 未来真实 AI 接入是独立设计任务，本版仅通过独立的示例展示模块保留替换边界。

## 8. 本地存储与备份

使用 IndexedDB 保存日记、关怀记录及独立示例副本。数据库名以应用名和发布路径命名空间隔离，避免同一 Pages 域名下其他项目误用。偏好包括当前空间、时间范围、减少动态效果和音量。数据结构携带版本号，升级时保留已有个人数据。

日记包含唯一 ID、发生时间及本地日期、整体感受、情绪、强度、事件、文字、创建和更新时间。关怀记录包含唯一 ID、活动类型、起止时间、结束日期、状态、可选前后评分及可选关联日记 ID；关联日记被删除时，保留活动本身并清除链接。

“数据管理”提供：

- 导出：导出个人日记与关怀记录为带版本号的 JSON；不混入示例，不自动下载。提示备份含私人内容、并非加密文件。
- 导入：第一版采用完整替换个人数据，不做含糊的自动合并。先校验版本、字段、数值范围、长度、时间与引用关系；预览记录数量并明确告知替换含义，用户确认后通过事务整体替换。取消或校验失败时原数据不变。导入上限 10 MB。
- 清空：二次确认后清空个人日记与关怀记录，不清除示例数据。

界面明确“记录仅保存在当前浏览器；清除站点数据或更换浏览器不会自动保留，请定期导出”。不将本地保存描述为加密或访问控制。不使用第三方行为分析脚本。

## 9. 技术结构与发布

拟采用 React + TypeScript + Vite 构建静态前端，以 CSS 实现视觉样式，使用轻量 SVG 图表呈现趋势。此为依据范围选定的技术方案，随本文一起审阅。

模块职责：

1. 页面层：记录、洞察、关怀、回顾、数据管理及首次入口。
2. 存储层：IndexedDB、空间隔离、版本迁移、备份校验和事务。
3. 分析层：无 UI 与存储依赖的纯函数，输入记录与时间范围，输出指标和依据 ID。
4. 关怀层：推荐规则、计时状态、音频控制及反馈保存。
5. 示例层：固定故事、可重置副本、固定 AI 示例材料。

数据流：表单校验 → 存储成功 → 重新读取当前空间记录 → 本地分析 → 展示指标与依据。编辑、删除、导入及清空后统一刷新相关视图。

使用 hash 路由，使详情链接及页面刷新无需服务端路由回退。资源路径支持 GitHub Pages 项目子路径。仓库配置 GitHub Actions 构建并发布静态产物；发布地址和仓库名在实施阶段依据实际仓库确定，不在此虚构。部署不包含日记数据、密钥或运行时 API。

音频随静态资源发布，实施时确认授权并记录来源；未取得可发布资源时不得用失效链接充当已完成功能。

## 10. 可访问性与异常处理

- 页面在 360px 手机到桌面宽度可用，正文不横向溢出，底部导航不遮挡表单操作。
- 控件具备标签、可见焦点、键盘操作和充分触控空间；情绪不只靠颜色表达。
- 图表同时提供文字摘要和可访问的数据列表，查看依据不依赖悬停。
- 尊重系统减少动态效果设置，提供静态呼吸文字节奏；音频须用户主动播放。
- 音频加载失败允许重试或换活动；本地存储不可用时明确提示，禁止显示保存成功。
- 导入与日记文字按不可信输入处理，文字不作为 HTML 执行。
- 数据为空、没有筛选结果、样本不足分别提供准确提示，不展示虚构占位统计。

## 11. 验收与验证

### 主要场景

1. 首次进入可选择两种空间，切换及重置示例不会污染个人记录。
2. 示例含连续两周材料，可展示趋势、事件比较、完整关怀反馈及带来源的 AI 示例。
3. 个人日记新增、补记、编辑、删除均真实保存，刷新后仍存在，分析随变更更新。
4. 缺失日期留空；一天多条均值正确；7／30 天范围边界、样本门槛、多标签去重规则正确。
5. 所有洞察可追溯对应记录；样本不足不显示比较结论。
6. 三类关怀活动可完成、暂停或退出相应流程；跳过评分不生成配对结果，负向变化如实显示。
7. 导出后可通过导入恢复；错误版本、非法数据及取消确认均不改变现有数据；清空须确认。
8. AI 示例清楚说明是预设内容，网络请求中无个人日记或模型调用。
9. 移动端布局、键盘交互、减少动态效果与音频失败提示可用。
10. 构建通过；发布后实际 GitHub Pages 首页、hash 详情刷新、项目子路径资源和音频均可访问。

### 验证方式

对分析公式、时间范围、标签门槛、导入校验和推荐映射编写有边界案例的单元测试。对 IndexedDB 持久化、空间隔离和导入原子性进行集成验证。浏览器验证记录到关怀到回顾的完整路径，并检查手机及桌面布局。真实发布后验证站点访问，不将本地构建成功等同于部署成功。
